# Protected pending magnet inbox

Roadmap 13 adds durable draft storage, with no routing, network request or automatic submission. It stores magnets only; torrent intake and payload migration belong to roadmap 15. Existing clients, NAS accounts and production data are untouched.

The app declares group.dev.bhanji.debrid in XcodeGen entitlements. PendingInbox.shared resolves that real App Group container or fails closed; there is no private/defaults/plaintext fallback. The PendingInbox directory, lock and newly created snapshot files use complete iOS file protection. The directory is excluded from backup. Actual isolated App Group writes and backup exclusion passed on the entitled simulator. Physical before-first-unlock/lock transitions and signed app/extension membership remain delivery checks. The declared entitlement does not provision Apple’s group or make the staged distribution profiles release-ready; authenticated website assignment and profile regeneration remain required.

One version1 inbox.json contains at most 32 drafts and 1 MiB of original URI bytes; serialized reads are bounded to 3 MiB. The first format has no legacy native inbox to migrate. Unsupported versions and malformed/corrupt/oversized state fail closed, preserving the original snapshot and partial files rather than inventing a reset. Later schema changes must explicitly migrate this version.

Each operation acquires a persistent BSD advisory lock using open(O_EXLOCK|O_NONBLOCK), with async 25 ms waits bounded to 2 seconds. After acquisition, all load/modify/save work is synchronous, with no suspension/network point while locked. Separate instances/processes use the same inode. Reads reject symlinks/nonregular files and bound allocation before decoding. Writes create an exclusive protected owned temp file, write/fsync completely, then atomically rename it over the snapshot. Recognized leftover temporary files are removed only after the existing schema validates. Unrelated files and corrupt/future snapshots are preserved. A process crash exposes an old or complete new snapshot; abrupt power-loss durability is not certified.

Exact original URI plus exact optional target-server URL determines duplicate saves. A different tracker/name/encoding or target stays a separate draft; the normalized v1 hash never discards raw options. Target hints are validated HTTPS roots without credentials; later submission must still validate the selected canonical profile and session. No API key, SSO token or Keychain secret enters this container. Item/claim descriptions and reflection redact private content.

Review leases have random tokens and a 120 second lifetime, with explicit renewal/release. Stale tokens cannot discard a reclaimed item. Wall-clock rollback beyond tolerance makes an old lease reclaimable; acquisition timeouts use a monotonic clock. A 30 day old draft is retained, still counts toward quota, and requires explicit keep confirmation before another review. Full storage never evicts accepted drafts. Review leases coordinate editing; they are not network idempotency. Roadmap 17 must persist/reconcile submission attempts before POST and preserve uncertain outcomes rather than relying on an expiring review lease.

Validation: 118 core Swift tests passed, covering exact roundtrip/restart/target dedupe, competing saves/claims, renewal/reclaim/stale tokens, expiration/keep, count/byte limits, corrupt/future/oversized state, deterministic partial-temp cleanup, preservation on unknown schema, symlink/FIFO refusal, actual group/protection/backup attributes, pre-start and held-lock cancellation, and redacted reflection. Simulator file-protection attributes are checked when reported; physical builds require complete protection. No simulator result certifies locked-device encryption behavior.

The bounded macOS host probe compiles the same production inbox/parser/address sources and runs two real processes. It passed concurrent duplicate/claim exclusion, busy timeout, killed-lock-owner recovery and writer process-death recovery. The timed writer kill can occur between writes; deterministic partial-temp unit tests separately cover orphan cleanup. Host permissions tests do not substitute for iOS data protection. This coordination follows Apple’s [shared-data technical note](https://developer.apple.com/library/archive/technotes/tn2408/) and [App Group configuration](https://developer.apple.com/documentation/xcode/configuring-app-groups).

Simulator and unsigned arm64 iPhone compilation/linking passed with the declared App Group entitlement. Independent source/test review approved. One reused simulator is shut down; one latest test result, the existing bounded build output and one host probe binary/cache remain. No new screen capture is needed for this storage-only increment.
