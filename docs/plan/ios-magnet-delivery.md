# Native magnet delivery and review handoff

Roadmap 14 registers the magnet URL scheme separately from the private Pocket ID callback scheme. Normal app scenes handle delivered magnet URLs on cold launch and while running. Authentication and unrelated schemes are ignored by intake; ASWebAuthenticationSession retains ownership of its authenticated callback. The coordinator has only an inbox interface and no server-mutation capability.

A valid link is persisted before a receipt appears. The native receipt offers Review, and a Pending links toolbar opens the durable queue during onboarding or connected management. Incoming links never automatically submit, replace an open review or cancel a sign-in. Review shows bounded name/hash/format/tracker metadata, a disclosure preview, keep-for-later and confirmed discard. Provider/category/file options and actual add belong to roadmap 17. The original link remains intact even when its preview is shortened; invisible formatting is escaped only for presentation.

The target hint is captured from the current authenticated profile before awaiting storage; later login/server changes never silently retarget that delivery. Exact duplicate receipts reuse the existing item. Failed saves retain up to 32 validated links in memory for explicit retry, with an honest keep-open message and no plaintext fallback. Input bursts and memory are bounded. Reopening a failed link successfully clears its retry entry, and discarding the last receipt clears the stale banner. Refresh revisions prevent stale snapshots replacing newer data; unreadable initial storage is distinct from an empty inbox.

Each review view has an owner ID. Claims and completion are generation/owner guarded, pre-cancelled work cannot invalidate a current view, and late acquired claims are released independently of caller cancellation. A cleanup-only token survives transient renewal failure while UI actions stay disabled. Active reviews renew every 30 seconds and end on background/disappearance. Expired/unclaimed rows can be discarded directly through native swipe/VoiceOver actions with confirmation, without extending unwanted retention. Store-side busy/token checks remain authoritative.

The operating system supplies a URL object, whose absoluteString is saved without another URL reconstruction. Raw text paste/share will use MagnetLink directly in subsequent milestones. Sender transformations before OS delivery cannot be recovered. The tested encoded URI retained its full parameter order, percent-escape case, repeated trackers and unknown fields exactly through real OS delivery and storage.

Apple documents [custom-scheme registration](https://developer.apple.com/documentation/xcode/defining-a-custom-url-scheme-for-your-app) and [SwiftUI URL delivery](https://developer.apple.com/documentation/swiftui/view/onopenurl(perform:)). Multiple apps registering a scheme have undefined target selection; this does not make Debrid a universal default magnet handler or override another app. Browsers may block or prompt for external protocols. On the tested iOS 27.0 simulator, simctl openurl returned success while the system still waited at Open in Debrid; delivery followed acceptance. Reliable user alternatives are explicit paste (15) and Share Extension (19); sharing a webpage does not imply sharing its magnet target. Real Safari/Notes/third-party-browser and competing-handler behavior remain device acceptance checks.
