# Paste and torrent documents

Milestone 15 adds native paste and `.torrent` import to the protected pending inbox. Neither path has a server mutation capability. Pending links is available before and after connection; its actions use the actual SwiftUI editor, PasteButton and system document importer. The existing web identity stays in restrained orange accents, warm list surfaces and SF typography; navigation, forms and sheets use system iOS 27 controls. Motion is limited to system presentation, with no decorative success animations.

PasteButton reads the clipboard only after an explicit tap. The editor accepts up to 16 line-separated magnets / 1 MiB of input. The whole batch validates before the first write; individual writes are acknowledged only after storage commits, and a later capacity failure can leave an honestly reported partial batch. Exact duplicates reuse a draft. Invalid/busy input stays in the editor. Input goes straight through MagnetLink, preserving parameter order, percent case and unknown fields; URL reconstruction and HTML/link extraction are absent.

The document importer requests `org.bittorrent.torrent`, declared as an imported data type with torrent extension and application/x-bittorrent MIME type. The app advertises alternate viewer support for external documents; URL delivery and picker selection share the bounded loader. Security-scoped access is balanced around a coordinated read; cancellation cancels pending coordination. The loader copies a regular file only, rejects final-component symlinks, checks cancellation while reading, and enforces 8 MiB even if the source grows. An original provider file is never edited or deleted. A non-scoped URL is accepted only within this app's own container or temporary directory; scope denial elsewhere fails closed. No bookmark or source URL is retained.

Native parsing accepts a deliberately bounded subset of server-supported v1/hybrid bencode. It hashes the exact original info dictionary bytes using the protocol-required SHA-1 and hashes the whole document with SHA-256 for copy integrity/deduplication. Canonical integers/key ordering, duplicate keys, UTF-8 display/path fields, safe path components, piece counts, arithmetic, nesting (32), nodes (100k), files (20k) and text lengths are checked. Binary dictionary keys in hybrid piece layers remain binary. Empty UTF-8 overrides follow backend fallback behavior. Hybrid payload size follows the v2 tree, excluding v1 padding; displayed file count follows the backend's v1 file view. V2-only metadata is rejected because providers require v1. Unknown fields are retained in the original bytes, never re-encoded. The backend upload limit remains 16 MiB; the native limit is intentionally smaller for bounded phone/extension memory.

## Protected storage version 2

An inbox record contains exactly one magnet or torrent metadata reference. Version 1 magnets migrate under the existing lock, preserving IDs, raw links, timestamps, targets and leases. Future schemas and corrupt manifests fail closed before cleanup.

Torrent payloads are separate UUID-named files, not base64 embedded in a repeatedly renewed JSON manifest. Each protected 0600 temporary copy is written and fsynced, then atomically renamed before its manifest reference commits. A process death before manifest commit leaves an unacknowledged orphan; the next valid transaction removes only owned UUID payloads/temporary writes. Explicit discard commits metadata first, then best-effort removes the now-orphaned copy. A cleanup failure never converts a committed operation into an ambiguous failure. This is logical removal, not a promise of physical secure erase.

Limits are 32 total drafts, 1 MiB magnet text, 8 MiB per torrent, 32 MiB total torrent copies and 3 MiB manifest. File protection/backup exclusion and cross-process locking continue to apply. Duplicate file receipts verify the existing copied bytes; review-time loading requires a live lease and checks count, SHA-256 and reparsed summary. Same-size damage cannot produce a successful duplicate receipt. Metadata snapshots avoid rehashing every file on every UI refresh. An in-memory retry queue holds at most 8 MiB total, with one document import at a time. Network attempt persistence/reconciliation remains milestone 17; review leases are not submission idempotency.

## Evidence and remaining acceptance

The generated corpus in testdata/ios-api/torrents.json comes from the real Go ParseTorrent function. It covers v1 single/multiple/empty data, empty UTF-8 fallbacks, hybrid padding and binary dictionary keys, v2-only and stricter native invalid-input policy. Swift tests check exact bytes/hash/name/size/file counts, malformed/oversize/cancelled input, original preservation, unsafe file types, duplicate/target scope, payload integrity, migration and owned orphan cleanup. Hosted simulator tests cannot certify physical locked-device protection or every third-party document provider. Physical Files/iCloud/provider selection, denied/revoked scopes, externally opened documents and lock/unlock remain device acceptance checks.

Final local checks: 140 core Swift tests passed. Five distinct native XCTest flows passed across light/dark runs: paste invalid-input retention/valid save/picker cancellation, exact-copy torrent review, largest-accessibility-size paste controls, and the two existing magnet handoff/large-text flows. The final dark run reran all 140 core tests plus the three document flows. Unsigned arm64 Release app/framework linking passed. Two real host processes verified magnet and torrent-copy duplicate exclusion, review claims, bounded lock contention and killed-process recovery. Independent source and actual four-frame light/dark visual review approved after resolving hybrid compatibility, paste saturation, cancellation and duplicate-copy integrity findings.

Captures came from the actual implementation's XCTest attachments on the shared iOS27.0 device (light result06:00:20, dark06:04:08, 2026-11-04), after ten-second settling. Torrent review used a UUID-isolated Debug fixture through the real document-copy/store/review path; it did not exercise an external provider. Paste capture had no clipboard content; the disabled system Paste control is intentional. Release ignores all fixture configuration. Only eight temporary PNGs and the latest relevant xcresult are retained; no new simulator/runtime/worktree was created.
